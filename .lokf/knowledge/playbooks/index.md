# Playbooks

* [Regenerate and test the schema](regenerate-and-test.md) - How to change the spdx schema: set up with uv and just, change scripts/spdx_to_linkml.py rather than the schema files, regenerate with just gen-linkml, gen-project, gen-doc and lokf-adapt, add examples, then run the checks CI runs (just test on Python 3.10 to 3.14, just lint and just lokf-adapt-check on 3.13) and the pre-commit hooks.
* [Release the schema](release.md) - How a releasing commit merged to main makes semantic-release promote the changelog's Unreleased section, tag vX.Y.Z and publish a GitHub Release, then dispatch the Knowledge Release workflow once KNOWLEDGE_RELEASE_ENABLED is true; below 1.0.0 from a v0.0.0 baseline tag, with a breaking change as a minor bump and nothing published to PyPI.
* [Move to a new SPDX release](move-to-a-new-spdx-release.md) - What to do when the upstream watch opens its issue: replace src/spdx_linkml/schema/upstream/spdx-model.ttl whole with the model the SPDX Project publishes for the new release, run just gen-linkml, then just lint, gen-project, gen-doc, lokf-adapt and test, and move the release's number and addresses in NOTICE, the README and lychee.toml.
* [Validate data against the schema](validate-data.md) - How to check a YAML or JSON file against the spdx schema with linkml-validate (for example with -C Package), why each object's type is a class CURIE such as spdx_software:Package, why a document in SPDX's own JSON-LD does not validate as it stands, and why the example runner cannot load an example with a from or import key.
* [Knowledge sources map](knowledge-sources.md) - The librarian's scrape map: every repository location and external page this bundle derives concepts from, the concepts each yields, how to re-check each on a refresh run, and the paths left out on purpose.
