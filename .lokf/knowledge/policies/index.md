# Policies

* [Security policy](security-policy.md) - How to report a vulnerability in spdx (GitHub's private vulnerability reporting, not a public issue), which release gets fixes, what the repository releases and runs, what holds each workflow, and the three repository settings not yet in force: required reviewers on the release Environment, a deletion and force-push rule on main, and secret scanning with push protection.
* [AI covenant](ai-covenant.md) - The rules for AI-assisted work in spdx: a contributor owns what they submit; the converter writes every schema element from the SPDX model, so a change goes into the converter with the part of the model it reads cited; the model copy is never edited; and the scheduled librarian works through pull requests a person approves, with least privilege.
* [License and attribution](license-and-attribution.md) - Which licence covers what in the spdx repository: Apache-2.0 for the schema, the generated models and the code; the SPDX 3.0.1 model copy under the Community Specification License 1.0, with the attribution it asks for; the SPDX examples under GPL-3.0; the linkml-project-copier scaffolding under MIT; the KTL sidecar and site templates under Apache-2.0; and the bundle under CC BY 4.0.
